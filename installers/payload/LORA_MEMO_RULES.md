# LoRA 分类与备忘填写准则

本文件是 `lora_notes.json` 和 LoRA 文件目录的本地权威规则。后续对话或其他 AI 处理 LoRA 时必须先读本文件。

## 1. 证据优先级

1. 用本地文件 SHA256 反查 Civitai 对应模型版本，确认模型类型、底模、版本和 `trainedWords`。
2. 读取 LoRA 同名 `.txt`；它对姿势、场景和多套服装的实际提示词优先级最高。
3. 读取 Civitai 当前版本的示例图片提示词，用于拆分角色、外貌和服装，或补足 `trainedWords` 为空的情况。
4. 读取 `.safetensors` 内的训练元数据（如 `ss_tag_frequency`）交叉核对。
5. 文档模板和人工推断只可辅助命名，不能覆盖模型页面或同名 TXT 的实际触发词。

禁止把中文标题、页面说明、模型简介、自动翻译句子或猜测内容当作英文触发词。

## 2. 文件识别和目录分类

- 以文件 SHA256 为身份依据，不仅凭文件名。
- 每个已安装的 `.safetensors` LoRA 旁边必须存在严格同名的 UTF-8 `.txt` 信息侧车；例如 `示例.safetensors` 必须对应 `示例.txt`。
- 新增、复制或重命名 LoRA 时，必须在同一次操作中创建或同步同名 TXT，不能只写面板备忘或导入清单。
- 已有同名 TXT 属于高优先级原始证据，批量补全时不得覆盖；只有经过页面、哈希或用户明确要求重新核对后才能更新其内容。
- 缺失 TXT 时，优先从已经核实的 `lora_notes.json`、导入清单和 Civitai 版本信息生成。没有可靠提示词时对应提示词保持空白并注明待核对，禁止猜测。
- 实际安装到模型目录的 `.safetensors` 文件名必须包含中文，不能只用英文、罗马字、数字或缩写。
- 汉化名应先写易懂的中文角色名或用途；必要时在中文后用括号保留英文原名、版本或作者标识，方便检索和追溯。
- 重命名时必须同步同名 `.txt`、预览图、元数据文件、`lora_notes.json` 键及面板内其他精确文件名引用；不得修改提示词中的真实英文触发词。
- 下载目录使用原始文件名，安装目录使用汉化文件名，并保存旧名到新名的审计清单。
- 从 `G:\edge download` 导入 LoRA 时默认执行移动，不保留下载目录中的 `.safetensors` 原件。必须先确定准确目标、生成面板备忘与同名 TXT，再移动模型文件；移动后复验目标 SHA256，确认与源文件一致。
- 如果目标已存在同一 SHA256，只能在确认安装文件、备忘和同名 TXT 均完整后移除下载目录中的重复原件；若目标存在但哈希不同，必须停止并报告冲突，不得覆盖。
- 与 LoRA 同名且确属其资料的 TXT、预览图或元数据应一起移动并同步汉化名称。不得因清理 LoRA 原件而删除下载目录中的压缩包、训练数据、图片、游戏文件或其他无关内容。
- Illustrious/NoobAI：
  - 服装：`Illustrious_Hosiery_Test/01_服装`
  - 人物：`Illustrious_Hosiery_Test/02_人物模板`
  - 通用功能：`Illustrious_Hosiery_Test/03_通用功能`
  - NSFW 姿势：`Illustrious_Hosiery_Test/04_姿势NSFW`
  - 场景：`Illustrious_Hosiery_Test/05_场景`
  - SFW 姿势：`Illustrious_Hosiery_Test/06_姿势SFW`
- Anima：使用 `Anima_Soft_Illustration` 下对应分类；人物放 `01_NSFW_人物`，服装放 `02_服装与丝袜`，功能放 `03_通用功能`，画风概念放 `04_画风与概念`，姿势放 `06_姿势`。
- SD1.5、Krea2 等不得混入 Illustrious 或 Anima 目录。

## 3. 顶层备忘字段

每个 LoRA 备忘包含：

- `title`：中文或便于阅读的显示名；可以附原名。
- `base_model`：按实际版本填写，例如 `Illustrious`、`Anima`、`SD 1.5`。
- `weight`：只写页面示例或作者明确支持的权重范围；不确定可留空。
- `trigger`：保持空字符串。面板不从此栏自动注入角色或服装词。
- `url`：对应 Civitai 模型页和准确的 `modelVersionId`。
- `outfits`：实际可应用的分项备忘。

## 3.1 同名 TXT 信息侧车格式

自动生成的同名 TXT 至少记录：显示标题、模型文件名、相对路径、SHA256、底模、建议权重、准确页面 URL 和顶层触发词状态。

每个分项按以下方式单独记录：

- 中文分项名称只写在“名称”行。
- 必须写明主类和实际字段，例如 `角色 / character / subject`、`服装 / clothing / clothing`。
- “提示词”下一行只写该分项的实际英文/ASCII 内容，不得混入中文翻译或说明。
- 顶层触发词继续保持空白；真实角色、外貌、服装、姿势、场景等提示词只进入对应分项。
- 页面没有触发词、备忘也没有可靠分项时，可以只记录版本信息，并明确写“未确认独立触发词”，不得为了填满 TXT 编造内容。
- 自动生成文件使用 UTF-8 编码，并在末尾保留换行。

## 4. 分项字段和主类

每个分项只填写与其主类对应的字段，并设置正确的 `main_class`：

| 主类 | `main_class` | 唯一主要字段 |
|---|---|---|
| 角色 | `character` | `subject` |
| 外貌 | `appearance` | `appearance` |
| 服装 | `clothing` | `clothing` |
| 姿势 | `pose` | `pose` |
| 构图 | `composition` | `composition` |
| 场景 | `scene` | `scene` |
| 光线 | `lighting` | `lighting` |
| 画风 | `style` | `style` |
| 上色 | `coloring` | `coloring` |
| 负面 | `negative` | `negative` |
| 其他 | `other` | `other` |

中文仅用于 `title` 和分项 `name`。`subject`、`appearance`、`clothing` 等实际提示词字段必须是模型需要的英文/ASCII 提示词，不得含中文。

## 5. 人物 LoRA 拆分规则

- “角色”“角色外貌”“服装”必须拆成不同备忘，不能都归到角色类。
- 角色备忘的 `subject` 只放独立角色/形态触发词，例如 `ExceedFate`。
- 外貌备忘只放头发、眼睛、肤色、体型、耳朵、尾巴、角、固定饰品等外貌特征。
- 服装备忘只放服装形态触发词和衣服、鞋袜、首饰、护具等服装标签。
- 页面没有独立角色触发词时，不得根据标题编造；可以只保存外貌与服装备忘。
- 同一 LoRA 有多个形态触发词时，为每个形态分别建立角色与外貌备忘；不要把互斥形态同时塞入一个预设。
- 服装的形态触发词若只对该服装生效，应保留在对应服装备忘中。

## 6. 服装、姿势和场景 LoRA

- 服装 LoRA：顶层 `trigger` 留空；每套衣服单独建立 `clothing` 备忘，触发词直接写在该备忘的 `clothing` 中。
- 姿势 LoRA：优先手动检查同名 TXT。TXT 中有多段不同姿势时，必须按 TXT 的每个真实姿势分别保存，不能套用文档里的单姿势格式。
- 只有一个触发词、一个姿势时，才可使用文档中的单姿势模板。
- 额外变体必须单独建立姿势备忘，保留原始姿势，不得冒充作者触发词。
- 场景 LoRA：把同名 TXT 或页面明确给出的场景词写入 `scene`；构图和光线仍应拆到各自主类。

## 7. 页面提示词的清理

- 删除质量词、采样器词、其他 LoRA 调用、作者画风串、场景和临时动作，只留下当前分项必需的内容。
- 不把完整示例提示词原样复制进角色或服装备忘。
- 保留大小写敏感或拼写特殊的真实触发词；明显拼写错误只有在页面示例和训练元数据共同证明可修正时才修正。
- Danbooru 常规标签可以统一逗号和空格，但不能改变专用触发词。

## 8. Embedding 与 LoRA 不混用

- Civitai 的 Embedding `Trigger Words` 是页面标识词；ComfyUI 标准文本编码节点加载时通常写作 `embedding:<标识词>`。
- Embedding 中文名只用于显示，不得成为文件路径或实际提示词。
- LoRA 不使用 `embedding:` 前缀。

## 9. 完成前检查

1. 文件底模与目标目录一致。
2. SHA256 与 Civitai 版本对应。
3. 顶层 `trigger` 为空。
4. 每个分项只有一个正确主类。
5. 角色、外貌、服装已拆开。
6. 所有实际提示词字段无中文。
7. 页面 URL 指向准确版本。
8. 面板 API 能看到新 LoRA 和备忘。
9. 每个已安装 LoRA 都有严格同名、非空、可读取的 UTF-8 TXT；全库扫描缺失数必须为 0。
10. 运行 JSON、分类、运行时/安装器一致性测试。
